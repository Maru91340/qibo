1. 项目是 Vue 3 + uni-app，微信小程序为主要端，H5 用于调试；页面通过 `src/pages.json` 管理，资料入口通过 `src/data/meta.js` 管理。
2. 当前 `pages.json` 有 52 个主包页面，另有 3 个分包：`pkg-character`、`pkg-qibo`、`pages-explore`。`meta.js` 当前定义 38 个首页板块入口。

## 三、核心页面实际代码位置

### 3.1 奇波列表

- 页面：`src/pages/qibo/list.vue`
- 路由：`/pages/qibo/list`

## 五、收藏、已收集、搜索、筛选、排序数据链路

### 5.1 收藏与已收集

已确认的收藏实现：

- `src/utils/favorites.js` 使用本地键 `qbxzs:favs`，上限 1000 条，记录 `type/id/name/icon/ts`。
- `src/pkg-qibo/detail.vue` 和 `src/pages/qibo/list.vue` 使用 `qiboWiki` 类型。
- `src/pkg-character/detail.vue`、旧角色详情和其他通用详情使用 `charWiki` 或图鉴类型。
- `src/pages/favorites/favorites.vue` 按类型分组，支持移除和最近浏览，不访问云端。

未发现的能力：

- 没有 `owned`、`collected`、`collection` 等独立前端状态或本地键。
- 没有已收集数、总数、收集进度条或“已拥有/已收集”按钮的数据源。
- `cloudfunctions/` 没有收藏/收集云函数，前端也没有用户身份、openid 或数据库写入调用。

因此规范中的“收藏”和“已收集”在当前项目只能先作为产品缺口记录。若要补齐已收集，必须先确定数据归属（本地还是云端）、登录身份、字段结构、权限和失败回滚方案，不能复用收藏字段冒充。

### 5.2 搜索

- `src/pages/search/search.vue` 通过 `getCatalog` 读取 meta、奇波、角色及 `SEARCHABLE_CATALOGS` 中的 12 类目录，然后调用 `searchAll`。
- 搜索发生在客户端内存中，覆盖名称、描述、分类、稀有度、技能和标签；结果按角色、奇波、各图鉴、板块分组。
- 搜索历史使用 `qbxzs:history`，最近浏览由 `src/utils/recent.js` 保存。
- 未发现输入防抖；输入事件会立即更新计算属性。
- 未使用云端关键词查询或数据库索引，因此当前不存在“前端无节制拉取远程分页”的实现，但整类目录会先同步到本地缓存。

### 5.3 筛选与排序

- 奇波列表的筛选状态完全在 `src/pages/qibo/list.vue`：元素、阶段、家园工种、种族、体型支持多选；草稿在底部面板确认后应用；`filterQibos` 负责组内或组间匹配。
- 角色列表的筛选状态完全在 `src/pages/character/list.vue`：定位、星级、元素单选组合；底部面板确认后应用。
- 奇波排序字段是编号升/降、名称升/降；角色排序字段是默认顺序、星级从高到低。均为前端排序，未调用接口。
- 奇波有“仅收藏”筛选，角色没有；两页筛选状态和 UI 组件也没有共享。
- 筛选选项来自当前目录字段或目录 `filters`，但奇波列表还会将 `qiboIndex` 编号骨架与 BWIKI 字段合并，字段缺失时可能造成“可见编号数据”和“筛选字段数据”来源不同。

## 六、云函数、云数据库、云存储与权限

### 6.1 云函数

`src/config/cloud.js` 配置共享资源 AppID、环境 ID 和三个云存储目录；`src/services/cloud.js` 通过 `new wx.cloud.Cloud({ resourceAppid, resourceEnv })` 初始化。

- `getCatalog`：公开读，支持 `manifest` 和 `content` 两种 action；读取 `catalog_manifests/published` 及对应快照，返回统一 `{ code, message, data }` 信封。
- `seedCatalog`：受控写；要求环境变量 `QBXZS_SEED_TOKEN`，使用常量时间比较；支持 status、publish、rollback；发布和回滚通过事务、版本冲突检查、哈希和审计记录保证一致性。
- `src/services/content.js`：启动时请求 manifest，按 revision 拉取变更类型，写入本地 `qbxzs:catalog-cache`；失败时继续使用内置资料。

### 6.2 云数据库集合

代码和云函数文档明确使用：

- `catalog_manifests/published`
- `catalog_snapshots/<type>-<hash前缀>`
- `catalog_manifest_history/<version>`
- `catalog_publish_audits/<runId>`

云函数代码未发现收藏、已收集、队伍或用户资料集合。

### 6.3 云存储

- `CLOUD_STORAGE_BASE`：`images/wiki/`，用于图鉴原图。
- `CLOUD_QIBO_CBT3_BASE`：`images/qibo-cbt3/`，用于奇波补图。
- `CLOUD_DETAIL_ASSETS_BASE`：`images/detail-assets/`，用于技能、资质、灵子、装备等详情素材。
- `src/data/site-images.js` 根据图鉴类型、用途和平台生成候选链；微信端优先 `cloud://`，H5 使用本地 `/static/wiki` 或热链回退。
- `src/services/cloud.js` 将 cloud fileID 按最多 50 个一批换成临时 HTTPS URL，并在会话内缓存。

### 6.4 权限结论与待核验项

代码仓库只看到云函数 `config.json` 的 `openapi: []` 和 `seedCatalog` 的环境变量鉴权，没有数据库集合权限规则文件，也没有云存储安全规则文件。文档要求四个目录集合“仅云函数写、审计/历史不允许客户端直接写”，但这必须在云开发控制台实际核验，不能仅凭仓库文件确认。

本阶段未访问云控制台，也未执行真实云读写，因此以下项目保持“待核验”：集合读权限、集合写权限、云存储 fileID 的读取范围、临时 URL 有效期、getCatalog 是否允许未登录调用、seedCatalog 环境变量是否已部署。
