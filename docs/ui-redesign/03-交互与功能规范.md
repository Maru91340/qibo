# 03｜交互与功能规范

## 已收集与已收藏必须独立

-   已收集（Owned/Collection）：表示用户在游戏内已获得/拥有。
-   已收藏（Favorite）：表示用户希望重点关注或稍后查看。
-   已收集用绿色勾选/状态标记，可展示 `已收集数 / 总数` 和进度条。
-   已收藏用星形图标，未收藏中性描边，已收藏金色或品牌强调。
-   收藏不代表拥有；收集状态不自动改变收藏状态。

开发前检查现有数据库字段、云函数、用户身份和权限。优先复用；不得猜集合名/字段名。若缺少其中一种能力，先提出数据模型、权限和迁移方案，得到批准后再改后端。云端失败必须反馈并回滚乐观更新；不能只改本地
UI 假装保存成功。

## 搜索

支持名称/编号搜索；输入防抖；清空入口明显；无结果有空状态和清除筛选入口。搜索与筛选共同生效。先检查现有云端查询和索引，不要在前端无节制拉取全部数据。

## 快捷筛选与更多筛选

快捷筛选优先元素、阶段、更多筛选，并显示当前值。更多筛选按真实字段分组，例如元素、阶段、家园工种、种族。明确单选/多选；显示选中态；提供重置、查看结果；底部适配安全区。快捷筛选和更多筛选必须共享状态。

## 排序

排序项只能来自实际可用字段。切换排序保留筛选；收集/收藏状态变化后相关计数刷新。

## 详情交互

收藏和已收集分离；图片预览；技能/阶段即时切换；折叠显示展开状态和条目数；关联卡片沿用原路由；编队/出战沿用原接口与校验。

## 吸顶导航

点击导航定位，滚动同步高亮；处理顶部偏移、异步图片、折叠展开后的定位变化。若双向联动不稳定，优先保证点击定位准确，不引入脆弱复杂逻辑。

## 易用性

触控区域建议不小于
40--44px；选中态不只依赖颜色；重要文字对比足够；按钮有加载/禁用态；网络失败可理解且可重试。
