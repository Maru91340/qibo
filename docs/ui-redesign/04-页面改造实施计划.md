# 04｜页面改造实施计划

## 阶段 0：只读审计

检查
`AGENTS.md`、`CLAUDE.md`、`README.md`、`package.json`、`pages.json`、`meta.js`；梳理页面、组件、主题变量、奇波/角色列表详情、收藏/收集/队伍/出战数据链路、云函数、数据库、云存储和权限。

先输出：页面清单、可复用组件、主题变量、状态数据链路、影响文件、风险。此阶段不改代码。

## 阶段 1：全局视觉基础

整理颜色、圆角、间距、字体、阴影、边框令牌；建立统一卡片、按钮、chip、徽标、搜索框、空状态和图片占位；浅色/深色同步。用奇波列表验证。

## 阶段 2：奇波列表

优化搜索、快捷筛选、更多筛选、结果工具栏、卡片；分别实现已收集/已收藏；补齐空、加载、失败状态。

## 阶段 3：角色列表

复用阶段 2 组件，突出角色立绘、稀有度、元素和定位，考虑角色数量增长。

## 阶段 4：奇波详情

优化
Hero、六维、技能、特性、基础信息、进化链、图志、经验和关联内容。只优化呈现，不删除数据、不改业务语义。

## 阶段 5：角色详情

实施吸顶导航 +
分类堆叠；语音、故事、推荐配置分组折叠；保留所有资料和队伍操作。

## 阶段 6：其他页面迁移

按使用频率逐步迁移：收藏夹/搜索/队伍 → 常用查询和养成工具 → 内容页面 →
低频工具。不要一次性改 38 个页面。

## 每阶段交付

修改前列出文件与理由；说明是否涉及接口/云函数/数据库/权限；小步实施；按
package.json 确认真实 build/lint/test 命令；检查 H5
和微信小程序端；输出修改清单、验证结果、未完成项和风险。

## 回滚

先确认 Git 工作区状态，不覆盖未提交改动；关键阶段建议独立
commit；不删除旧组件/字段/云函数，除非确认无引用且获批准；数据迁移与纯
UI 改版分开。
