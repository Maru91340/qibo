## 3. 关键发现：CDN 缩略图不是任意宽度可取

- `patchwiki.biligame.com` 只提供**站点已生成过**的宽度。实测：`Tex_icon_hero_l_101008.png` 的 240px 可用而 120px 不可用；`卫星-丝绒.png` 的 80/120/160px 可用而 200/240px 不可用；`Tex_icon_pet_500041.png` 的 100/200/240/320px 可用。
- 直接拼「用途宽度」时首轮核验为：avatar 1/24、art 23/24、攻略 poster 3/22 可达。用站点 `Special:Redirect/file/<文件名>?width=N` 可按需生成并返回 302 到直链（中文文件名、长图封面均实测 200）。
- 处理：候选链 = **用途新图 CDN 直链 → 同图按需生成地址 → 原有 `icon` 热链**；页面 `@error` 逐档切换。构建期对已映射文件做过一次性预热（仅 GET 已存在文件的按需生成地址，不采集、不下载、不回写数据），复探后 avatar 24/24、art 24/24、poster 22/22、主视觉 2/2 首图可达。
- 风险：CDN 可能淘汰缓存，且**微信 `<image>` 对跨主机 302 的表现本轮未在开发者工具验证**，所以按需生成地址保留在候选链中而不是依赖一次性预热。

## 8. 风险与遗留

1. 主包硬上限只剩 33.3 KiB。阶段 2.4 若用 `--full-icons` 扩展其余类型映射（约 300+ 条新增 URL）会逼近或超过硬上限，必须先确定图片分发方式（见本轮新增待确认 #21）。
2. 仍维持第三方 CDN 热链：可用性、授权（#16）与缓存淘汰均非本地可控；微信端对 `Special:Redirect` 302 的实际表现未验证。
3. 旧云端缓存仍可能压制磁盘新数据（#20），本轮所有结论都**不能**表述为运行界面已生效。
4. 2.5「统一缺图回退」只完成候选链与等尺寸占位基础，尚未在所有图鉴/首页统一首字剪影、重试入口与失败不改布局的实测。
5. 2.6 首屏预算、T06 逐项视觉核对、T01–T12、浅/深色实拍均留待后续轮次与真机回归。
