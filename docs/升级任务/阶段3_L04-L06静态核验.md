## 3. 3.3 / L05 示例、重复与「待核实」

### 3.1 为什么不改数据层

`npm run check` 会用 esbuild 打包 `src/data/catalog.js` 及其数据依赖生成云端 seed 修订号。若在数据层删示例/去重，seed revision 会变，而 `CATALOG_VERSION` 仍由 `generatedAt` 决定不会变，会加剧阶段 1 已查明、且 #20 默认跳过不处理的「版本键相同、内容不同」问题。故本轮采用**视图层统一过滤**（`officialItems`），并在核验脚本里加了一条 seed 修订号一致性断言，实测仍为 `629031e7f2ac426d`，数据层输出零改动。是否下沉到数据层见待确认 #23。

### 3.2 数据口径实算（打包 `catalog.js` 取真实 `bundledCatalog` 后套 `officialItems`）

| 类型 | 原始条目 | 识别为演示 | 额外同名重复 | 正式列表 | 正式列表重名 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 角色 | 32 | 6（手工艾妮丝 + 5 个「示例·」） | 0 | 26 | 0 |
| 奇波 | 215 | 6（7 只示例中「森彩灵蝶」手工条目已被数据层既有按名称去重剔除） | 0 | 209 | 0 |

正式列表仍包含 BWIKI 收录的「艾妮丝」，以及竞品补充「星裔（女）」「熔焰烬龙」「菜鸡（特殊）」；演示条目与同名重复均已排除。

### 3.3 标签与来源

- 奇波列表原来**无条件**给每张卡贴「待核实」，而 `mapWikiQibo` 又统一设 `verified: true`，两个表达方向相反。现改为 `v-if="item.verified === false"` 才显示「字段暂缺」，并用局部 `.mini-tag--muted` 降级，不与名称抢视觉等级；角色页与通用图鉴同步。
- 来源说明集中在页面底部 `LIST_SOURCE_NOTE`：「资料来自 BWIKI 玩家 Wiki 收录 · 收录不等于官方核实 · 公测前字段可能变动，缺项标『字段暂缺』」，不再逐条铺标签。
