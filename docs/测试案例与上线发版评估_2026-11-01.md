### 2.2 `npm test` ✅（2026-11-01 修复后 10/10 全绿）

> 原状态：1 个用例失败（`makeManifest refuses an incomplete catalog`，根因为测试 fixture 未跟上 17 类扩容）。已修复，并新增 2 个覆盖用例。以下为原始根因分析，留档。

```
✖ makeManifest refuses an incomplete catalog and merges partial updates
  Error: spirit payload must be an object  (code: INVALID_CONTENT, details: ['spirit'])
  at cloudfunctions/shared/catalog-core.js:302 → tests/catalog-core.test.js:158
```

**根因分析（已定位）**：这是**测试用例未跟上 schema 扩容**，不是生产代码 bug。

- `cloudfunctions/shared/constants.js` 的 `CATALOG_TYPES` 已从最初 4 类扩到 **17 类**（新增 spirit/item/…/guide）。
- 但 `catalog-core.test.js` 的 `built()` 工厂仍只内置了 4 类的合法 payload（`{ meta, element, qibo, character }`），遍历 `CATALOG_TYPES` 时 `spirit` 取到 `undefined` → `normalizeContent` 按设计抛错 → 断言失败。
- 该用例实际验证的两件事（不完整目录拒绝发布 / 增量合并保持修订号稳定）逻辑本身没有回归，但**用例失效意味着这 17 类下的 manifest 合并逻辑目前是零覆盖**。

**已实施修法**：
1. 补 `validEntries()` 最小合法 fixture，13 个通用图鉴类（normalizeEntries schema）共用；
2. 新增用例「every CATALOG_TYPE accepts a minimal valid payload」——逐类验证，防再犯「扩类型忘更测试」；
3. manifest 用例改为 17 类精确断言（不完整目录的缺失清单按 CATALOG_TYPES 动态计算）；
4. 新增边界用例「items limit is enforced at exactly LIMITS.items entries」——恰好 500 条可发布、501 条拒绝（对应 R1 的回归保护）。

### 2.3 未自动化覆盖的层

### 4.1 设计系统 ✅ 做得对的
1. **Token 化完整**：`theme.css` 635 行，全部颜色/圆角/阴影走 CSS 变量（`--brand/--ink/--card-bg/--radius-*/--shadow-*`），并与 TDesign 的 `--td-*` 变量做了桥接（brand/text/radius 对齐），组件库和自绘 UI 视觉同源。

## 六、图片资源是否需要上传云开发？——**需要，建议首版就做**

### 现状
- 内置资料中 **1,118 张图片全部是 `patchwiki.biligame.com` 外链**（BWIKI 图床），小程序包内 `src/static` 无自有图片资源。
- 小程序 `<image>` 组件加载外链**不需要**域名白名单，所以「现在能跑」，这也是它一直没暴露的原因。

### 为什么仍要迁（三个理由，按严重度）

1. **可用性不受自己控制（可用性风险）**
   - BWIKI 图床 URL 带 `/thumb/…/120px-…` 路径，站点改版、缩略图规则调整、反盗链策略开启（Referer 校验）任一发生，1,118 张图**全站同时失效**，且你没有任何缓存副本。第三方图床对小程序 referer 的放行是「事实上能跑」而非「承诺能跑」。
   - 云存储迁移后走微信云 CDN，可用性与小程序生命周期绑定。

2. **审核与版权合规（合规风险）**
   - 直接热链第三方站点图床做商业展示，提审被认定「侵犯他人权益」的概率不低；迁移到云存储不能改变素材来源的版权属性，但把**可控性**拿到自己手里：可以按需替换为官方渠道素材、可以一键下架。

3. **体验可控**
   - 自己控制缩略图尺寸（现在混用 120px 缩略图与原图），可以做列表用小图/详情用大图两级；云存储 fileID 可直接作为 `<image>` src，**同样不需要域名白名单**。

### 不迁移的代价对比
| 方案 | 可用性 | 合规 | 白名单 | 成本 |
|---|---|---|---|---|
| 现状：外链 BWIKI | 随时全挂 | 弱 | 不需要 | 0 |
| **云存储（推荐）** | 自控 + 云 CDN | 中（素材来源仍需注意） | 不需要（cloud:// fileID 直用） | 流量几乎免费额度内 |
| 自有服务器/CDN | 自控 | 同上 | 需配 downloadFile 域名 | 域名+HTTPS+备案 |

### 建议迁移方案（约半天）
1. 写脚本读取 `src/data/generated/catalogs.json`，收集全部去重 URL（约 1,118 张，缩略图为主，估计总量 < 200MB）。
2. 用云开发控制台批量上传，或写 Node 脚本 `wx-cloud upload`（tcb CLI / `@cloudbase/manager-node`）上传到云存储，按 `catalog/<type>/<id>.png` 规范命名。
3. 发布脚本把 payload 里的 URL 字段批量替换为 `cloud://` fileID（`getCatalog` 返回原样，`<image>` 直接支持）。
4. `seedCatalog` 重新发布全部 17 类；客户端冷启动自动增量拉取。
5. 保留 BWIKI URL 作为 fileID 失效时的 `@error` 二级回退（组件已支持 @error，改回退 src 即可）。
