## 3. 当前项目问题清单

### P0-1 角色/奇波列表数据绑定错误（核心图鉴不可用）

**影响页面**：`/pages/character/list`、`/pages/qibo/list`  
**证据**：[角色列表首屏](./ui-test-2026-10-31/qbxzs-03-character-list.png)、[角色列表底部](./ui-test-2026-10-31/qbxzs-04-character-list-bottom.png)、[奇波列表](./ui-test-2026-10-31/qbxzs-13-qibo-list.png)、[筛选五星后](./ui-test-2026-10-31/qbxzs-14-character-filter-five-star.png)

**现象**（复现率 100%）：

1. 计数文案显示为“**共 名角色**”“**共 只奇波**”，数字为空。
2. 列表底部同时出现真实卡片与 **4 张空白“幽灵卡”**：只有“示例”标签和两个空色块，无名称、无描述。
3. 页面底部**始终显示**“没有符合条件的角色 / 奇波”空态，即使列表有 6/7 条数据。
4. 点击幽灵卡会进入详情页并显示“未找到该角色”。
5. 筛选和搜索本身有效（五星：10 张卡 → 7 张；搜索“艾妮丝”：→ 5 张），但计数与空态不随之变化。

**根因**：`decorateWithElement()` 设计为接收**单条对象**，但两个列表页把**数组**直接传了进去。

- [`src/pages/character/list.vue:108`](../src/pages/character/list.vue#L108)
- [`src/pages/qibo/list.vue:122`](../src/pages/qibo/list.vue#L122)
- [`src/utils/query.js:11`](../src/utils/query.js#L11)

```js
// 现状：把数组传给单条装饰函数
const list = computed(() =>
  decorateWithElement(
    filterCharacters(catalog.value.items, { keyword, role, rarity, element }),
    elementToolkit.value.elementMap
  )
);

// query.js：Object.assign({}, item, {...}) 把数组摊成了普通对象
export function decorateWithElement(item, elementMap) {
  const element = elementMap[item.element] || {};
  return Object.assign({}, item, { elementName, elementColor, elementTint, elementLabel });
}
```

数组被 `Object.assign` 后变成普通对象：`0..N-1` 是真实条目，另外多出 `elementName/elementColor/elementTint/elementLabel` 4 个字符串键，因此 `v-for` 遍历出 **N+4 张卡**；对象没有 `length`，所以计数为空、`v-if="!list.length"` 恒为真。

**修复**：

```js
// character/list.vue
const list = computed(() =>
  filterCharacters(catalog.value.items, {
    keyword: keyword.value,
    role: role.value,
    rarity: rarity.value,
    element: element.value
  }).map((item) => decorateWithElement(item, elementToolkit.value.elementMap))
);

// qibo/list.vue 同理
const list = computed(() =>
  filterQibos(catalog.value.items, { /* ... */ })
    .map((item) => decorateWithElement(item, elementToolkit.value.elementMap))
);
```

建议同时在 `query.js` 增加防呆，避免同类误用再次发生：

```js
export function decorateWithElement(item, elementMap) {
  if (Array.isArray(item)) {
    return item.map((entry) => decorateWithElement(entry, elementMap));
  }
  // ...
}
```

**回归断言**：

- 角色列表初始：`共 6 名角色`，`.entry-card` 数量 = 6，空态不存在。
- 选择“五星”：`共 3 名角色`，卡片 = 3，无幽灵卡。
- 搜索“艾妮丝”：`共 1 名角色`，卡片 = 1。
- 奇波列表初始：`共 7 只奇波`，卡片 = 7。
- 控制台无重复 `key` 警告（当前幽灵卡共用 `undefined` key）。

### P1-1 筛选栏默认全展开且 sticky 常驻，压缩浏览区

**证据**：[角色列表](./ui-test-2026-10-31/qbxzs-03-character-list.png)、[列表底部仍常驻](./ui-test-2026-10-31/qbxzs-04-character-list-bottom.png)、[物品筛选展开](./ui-test-2026-10-31/qbxzs-08-item-facet-open.png)

- 角色列表 `.filter-bar` 实测 **365×203 px**，占 844px 视口的 **24%**，且 `position: sticky; top: 0`（[`src/styles/theme.css:177`](../src/styles/theme.css#L177)）。滚动到列表底部时仍固定占据 203px。
- 5 行 chip（定位 / 稀有度 / 元素）无折叠入口，用户无法临时隐藏。
- 物品列表的 facet 展开后一次展示 **21 个分类 chip**，高度接近整屏；展开状态吸附在顶部，列表只剩 2 条可见。
- 受 `.filter-bar` 影响的页面共 **7 个**：角色、奇波、成就、凶兽、图鉴百科、攻略、壁纸。

**建议**：默认收起为单行“搜索 + 筛选（n）”，筛选放进底部抽屉；抽屉内提供“重置 / 确定”，并让 sticky 只作用于收起态。参考项目同页的筛选入口只有一行按钮（**42px**，不含搜索框），且展开后仍能看到 3 条列表。

.content-card__cover { display: flex; align-items: center; justify-content: center; height: 200rpx; overflow: hidden; }

/* 方案 A：全宽封面 */
.content-card__cover { height: 200rpx; }

/* 方案 B：左文右缩略图 */
.content-card__cover { width: 160rpx; height: 160rpx; flex: none; }

### P1-3 首页 Banner CTA 被裁切

**证据**：[首页顶部](./ui-test-2026-10-31/qbxzs-01-home-top.png)  
**代码**：[`src/pages/index/index.vue:194`](../src/pages/index/index.vue#L194)、[`:293`](../src/pages/index/index.vue#L293)

- Banner 固定高 **156px**（300rpx）且 `overflow: hidden`。

### P1-4 浅色主题次要文字对比度不达标

**证据**：[角色列表计数](./ui-test-2026-10-31/qbxzs-03-character-list.png)、[设置深色](./ui-test-2026-10-31/qbxzs-11-settings-dark.png)  
**代码**：[`src/styles/theme.css:7`](../src/styles/theme.css#L7)

| 组合 | 对比度 | WCAG AA（正常字号 4.5:1） |
| --- | --- | --- |
| `--ink-3 #97a0b5` on `--bg #f3f5fb` | **2.40:1** | 失败 |
| `--ink-3 #97a0b5` on `#ffffff` | **2.62:1** | 失败 |
| 深色 `--ink-3 #7d879f` on 卡片 `#1c2233` | **4.40:1** | 临界失败 |

用于 `.section-title__more`（板块计数）、`.text-muted`、`.footnote` 等 **22–24rpx（约 11–12px）** 小字，属于正文级信息，不适用“大字号 3:1”豁免。

**建议**：浅色 `--ink-3` 改为 `#667089`（4.54:1）；深色改为 `#8b95ad`（5.28:1）。注意这与“保持灰阶层级”不冲突，`--ink-2` 可保持现状。

### P1-5 浅色主题卡片配图几乎不可见（且配图语义错配）

**证据**：[首页卡片](./ui-test-2026-10-31/qbxzs-01-home-top.png) vs [深色首页](./ui-test-2026-10-31/qbxzs-12-home-dark.png)

- 卡片配图：`opacity: 0.5` + 白色渐变遮罩在 58% 处仍为 `rgba(255,255,255,0.86)`（[`src/pages/index/index.vue:361`](../src/pages/index/index.vue#L361)、[`:375`](../src/pages/index/index.vue#L375)），右侧有效可见度约 **0.44**；参考项目为 `0.72 × 0.82 ≈ 0.59`，且使用全身透明底立绘。
- 结果：浅色下图卡只剩“幽灵人脸”，用户第一眼会误判为图片加载失败；深色下反而正常。
- 配图来源是 `spiritItems` 图标的哈希随机取图（[`src/pages/index/index.vue:136`](../src/pages/index/index.vue#L136)），**“装备图鉴”卡可能配一张角色脸**，与板块语义无关。

**建议**：降低白色遮罩强度（58% 处 ≈0.72）、把配图 opacity 提到 0.72；为每个板块配置语义匹配的固定图（角色/奇波/装备/材料），不要用哈希复用。素材建议使用透明底立绘，避免方形头像被裁。

### P2 级问题

#### P2-1 深色模式导航栏仍是亮蓝

- `pages.json` 的 `navigationBarBackgroundColor` 固定为 `#1F3D9E`，深色页面顶部出现一条亮蓝色横条，割裂感明显。
- 建议在主题切换时调用 `uni.setNavigationBarColor({ frontColor: '#ffffff', backgroundColor: '#131722' })`，或改用自定义导航栏。

#### P2-2 计数信息重复 / 空值

- 物品列表同时出现“**命中 300 条**”“**共 300 条**”两个完全相同的数字；分页后底部又出现“已显示 60 / 300 条”，同屏三处计数。
- 建议保留一处主计数（命中/总数不同才有意义），分页按钮内只显示进度。

#### P2-3 品牌名四处不一致

| 位置 | 文案 |
| --- | --- |
| `src/manifest.json:2` | 蓝色星原**助手** |
| 首页导航（`pages.json`） | 蓝色星原 |
| 设置页脚（`settings.vue:43`） | 蓝色星原**手册** · 非官方资料站 |
| 参考目标截图 | 蓝色星原**手册** |

建议统一为“蓝色星原手册”，并同步小程序简称、分享标题、关于页。

#### P2-4 53 个页面没有全局导航

- `pages.json` 无 `tabBar`，首页 37 个板块是唯一入口；进入深层页后只能逐级返回。
- 参考项目用“我的”聚合页 + 全局“全部功能”FAB 缓解，当前项目两者都没有。
- 建议至少提供 `首页 / 图鉴 / 工具 / 我的` 四项 Tab，或全局功能面板；否则新增页面越多，可达性越差。

#### P2-5 面向用户的内部术语过多

- 首页分组标题直接显示“**工具 · 低优先级**”（[`src/pages/index/index.vue:116`](../src/pages/index/index.vue#L116)）。
- 图鉴脚注：“数据采集自 **BWIKI**（wiki.biligame.com/ap），**抓取**于 2026-10-30”。
- 设置页：“**BWIKI**（公测后以官方为准）”“当前为**内置资料，云端尚未同步**”“清除**云端**资料缓存”（实际清的是本地缓存）。
- 订阅页：“消息模板配置后才会真正推送”“推送方式：订阅消息（**待配置**）”。
- 这些是开发/数据状态，不是玩家语言；建议改为“资料更新于 10-30 · 公测后以官方为准”“数据仅保存在本机”等，并给未上线能力加“即将开放”而不是“待配置”。

#### P2-6 自绘开关的热区与状态辨识不足

- 订阅页开关 88×48rpx = **45.8×25 px**，低于 44px 推荐触控高度；关闭态轨道 `#f2f4f9` 与白卡对比约 **1.1:1**，截图中几乎只看到白色圆点。
- 建议轨道改 `--line` 更深一级或加内阴影，高度提到 56–64rpx，并补充 `aria-checked` / `role="switch"` 等价语义（mp 可用 `checkbox` 或可访问性属性）。

#### P2-7 筛选面板没有“重置”入口

- `catalog-list` 的清空筛选只在**结果为空**时出现（[`catalog-list.vue:87`](../src/components/catalog-list/catalog-list.vue#L87)）；用户选了 10 个分类后想恢复全部，只能逐项点“全部”，或先制造空结果。
- 参考项目在筛选区直接提供“重置”。建议面板底部常驻“重置 / 收起”。

#### P2-8 筛选 chip 横向溢出无提示

- 教程顶部分类右侧“战…”被直接切断；参考项目“阵营”行“三分之地”也被裁切，两边都有此问题。
- 建议容器右侧加渐隐遮罩 + 首次进入的横向滚动提示，或改成“换行 2 行 + 更多”。

#### P2-9 无加载态/骨架屏，图片全量远程热链

- 879 张图片全部指向 `patchwiki.biligame.com`，无本地缓存兜底；弱网或 CDN 波动时首屏会出现大面积空白。
- 页面没有 skeleton/loading，数据同步渲染时是“白屏→突然出现”。
- 建议首屏 6–8 个卡片做骨架占位，图片加 `lazy-load` 与失败占位，关键图（Banner、首页图卡）落本地或 CDN 自有域名。

#### P2-10 列表底部未处理安全区

- 全仓无 `env(safe-area-inset-bottom)`；iPhone 全面屏下最后一屏内容可能贴近 Home Indicator。
- 建议 `.page { padding-bottom: calc(24rpx + env(safe-area-inset-bottom)); }`，悬浮操作条另加。

#### P2-11 物品分类数据未归一化

- 筛选面板出现“材料、材料、星结卡”“料理材料、材料”“角色礼物、牵绊礼物”等拼接值，粒度不一致且重复“材料”。
- 说明采集层把多分类原文直接拼成字符串。建议在生成阶段拆成 `categories: []`，筛选按单个分类匹配，避免选项爆炸（当前 21 项）。

#### P2-12 H5 端 TDesign 组件不可用（工程风险）

- 直接 `dev:h5` 打开当前项目，`t-*` 组件全部解析失败，页面空白；本次必须依赖临时 shim 才能走查。
- 若产品需要 H5 预览/分享/海报页，应在构建层做条件编译降级（uni 官方组件或轻量自绘），否则 H5 产物不可用。
- 同时，订阅提醒目前是“本地记录 + 待配置推送”，建议在功能真正可用前隐藏入口或明确标注“实验功能”。

## 5. 与参考小程序截图的对比

> 参考截图来自“蓝色星原手册”（同一个 IP、同一个目标用户），因此它比 `wxq-uniapp` 更能代表“应该长什么样”。以下只谈结构性差距，不要求像素级照搬。

### 5.1 品牌与视觉语言

| 维度 | 当前项目 | 参考小程序截图 |
| --- | --- | --- |

| 主色 | 品牌蓝 `#2f6bff` + 蓝紫渐变 | 橙色强调 + 黑色胶囊 + 元素彩色徽章 |
