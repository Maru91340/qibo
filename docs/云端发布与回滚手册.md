# 云端发布与回滚手册

> 适用于 `getCatalog` / `seedCatalog`。正式客户端不包含管理入口；所有写操作只在云开发控制台或受控运维环境执行。

## 一、发布前条件

1. 本地工作区已形成可追溯版本，执行 `npm ci` 与 `npm run release:check`。
2. `cloudfunctions/getCatalog`、`cloudfunctions/seedCatalog` 均已部署当前构建产物。
3. `seedCatalog` 环境变量 `QBXZS_SEED_TOKEN` 已设置为至少 32 字节随机串，且未进入代码、命令历史、日志或截图。
4. 云函数 Node 运行时与 `.nvmrc`/发布记录一致。
5. 已确认当前依赖审计；Critical 未关闭时不得正式发布。

## 二、读取当前状态

在云开发控制台对 `seedCatalog` 执行：

```json
{
  "action": "status",
  "token": "<仅在控制台临时填写>"
}
```

保存返回的 `version`。未发布过时，返回 `published: false`，后续 `expectedVersion` 使用 `null`。

## 三、发布内置资料

先执行 `npm run seed:export` 并重新构建、部署 `seedCatalog`。随后调用：

```json
{
  "action": "publish",
  "source": "bundled",
  "expectedVersion": "<status 返回的 version；首次为 null>",
  "token": "<QBXZS_SEED_TOKEN>"
}
```

增量发布使用 `source: "manual"`，并传入非空的 `content` 对象：

```json
{
  "action": "publish",
  "source": "manual",
  "content": {
    "item": { "notice": "...", "items": [] }
  },
  "expectedVersion": "<status 返回的 version>",
  "token": "<QBXZS_SEED_TOKEN>"
}
```

`VERSION_CONFLICT` 表示期间已有其他发布：重新执行 `status`、核对变更，再决定是否重试；禁止盲目替换版本号。

发布成功后记录：代码 commit/tag、小程序版本、云函数部署时间、`runId`、`previousVersion`、新 `version`、各类型 count/revision。

## 四、发布后验证

1. 用 `getCatalog` 读取 manifest，确认 revision 等于新 version。
2. 读取本次变更类型的 content，核对条目数和关键数据。
3. 体验版真机冷启动，确认能同步新 revision。
4. 断网重启，确认内置资料仍可使用。
5. 检查 `catalog_publish_audits/<runId>` 与云函数结构化日志。

## 五、回滚

先读取当前 status，确认 `expectedVersion`；从发布记录中选择历史 `targetVersion`：

```json
{
  "action": "rollback",
  "targetVersion": "<要恢复的历史 version>",
  "expectedVersion": "<当前线上 version>",
  "token": "<QBXZS_SEED_TOKEN>"
}
```

云函数会在事务中：

- 校验当前 version 未变化；
- 读取不可变 manifest history；
- 校验 17 类 snapshot 的类型、状态、SHA-256 和实际 payload 哈希；
- 原子切换 published manifest；
- 写入回滚审计。

回滚完成后重复“发布后验证”。若返回 `ROLLBACK_INVALID`，不要手工修改 published manifest，应先检查历史快照是否缺失或损坏。

## 六、紧急处置

- Token 疑似泄露：立即在云函数环境变量中轮换，重新部署/验证；不要复用旧 Token。
- 发布冲突：停止重试，核对 `catalog_publish_audits` 和最新 status。
- 客户端同步异常：优先回滚 manifest；客户端会保留旧缓存或退回内置资料。
- 数据库写异常：保留 `runId` 和日志，不删除内容寻址 snapshot；未被 manifest 引用的快照不会被客户端读取。
