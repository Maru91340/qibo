# 云开发接入备忘（AGENTS.md「云开发接入」的细节补充）

## CAM 子账号策略（两条缺一不可）

文件上传链路：`storage.getUploadMetadata`（TCB 数据面接口，`tcb:*` 覆盖）
→ **COS `putObject` 直传环境共享桶**（需 COS 权限，TCB 预设策略不含！）。
只挂 `QcloudTCBFullAccess` 时症状：元数据接口正常、文件写入报 `Access Denied.`。

1. `QcloudTCBFullAccess`（预设策略）
2. 自定义策略 `qbxzs-tcb-storage-upload`（按策略语法创建，粘贴以下 JSON）：

```json
{
  "version": "2.0",
  "statement": [
    {
      "effect": "allow",
      "action": [
        "cos:PutObject",
        "cos:InitiateMultipartUpload",
        "cos:UploadPart",
        "cos:CompleteMultipartUpload",
        "cos:AbortMultipartUpload",
        "cos:ListMultipartUploads",
        "cos:ListParts",
        "cos:GetObject"
      ],
      "resource": [
        "qcs::cos:ap-shanghai:uid/1485155108:636c-cloud1-d7gx1tocd9762a9ba-1485155108/*"
      ]
    }
  ]
}
```

（桶与地域来自 `src/config/cloud.js` 解析：桶 `636c-cloud1-d7gx1tocd9762a9ba-1485155108`，地域 `ap-shanghai`；换环境时同步改这里的 uid/桶名。）

## 上传链路参考

- SDK：`@cloudbase/manager-node` → `storage.uploadFile({ localPath, cloudPath })`
  = `getUploadMetadata`（`POST tcb-api.tencentcloudapi.com/admin`，action `storage.getUploadMetadata`）
  + COS putObject（`x-cos-meta-fileid` 区分上传者，丢了会导致 fileID 无法反查）。
- 错误诊断顺序：`Access Denied.` 先分清来自数据面还是 COS 层——单步调
  `app.storage.getUploadMetadata('x.png')` 通、`uploadFile` 拒 = COS 权限缺失。
- CAM 策略变更后约 1-2 分钟生效延迟，先等再重试。

## MP 运行时坑（2026-11-19 排查实录）

- **微信小程序运行时没有 `URL` 构造器**：`cloudDetailAsset` 曾用 `new URL(url).pathname`
  解析链接，MP 端抛错被 try/catch 静默吞掉 → 直接返回原始外链 → 上传了云图也不生效，
  详情页仍打 csxylic 热链（H5 端因浏览器有 URL 而正常，极具迷惑性）。已改为手动
  `raw.replace(/^https?:\/\/[^/]+/i, '')` 截取 pathname。全仓库禁止再对 MP 代码使用 `new URL`。
- 由此连带发现：`detail-assets/装备` 分类（tex_icon_equipment_* / tex_accessory_*，107 个）
  从未整理进上传批次——正是热链回退掩盖了缺图。补采脚本 `scripts/collect-character-detail.py`
  扫描 character-detail 三数据源全部图标并核对分类覆盖，可重复跑。
